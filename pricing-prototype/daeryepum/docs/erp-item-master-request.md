# ERP 품목마스터 연동 요청 (초안)

작성 2026-08-05 · 답례품 재고 관리 화면 개발 중 확인된 사항 정리
수신 예정: ERP 담당 / DBA

---

## 1. 현재 넘어오는 데이터

`bar_shop1` 을 전수 조사한 결과, ERP → 쇼핑몰 DB 로 넘어오는 답례품 데이터는
**`S2_CARD_ERP_STOCK` 테이블 한 장**뿐입니다. (답례품 기준 175행 / ERP코드 156 / 품목코드 166)

| 구분 | 컬럼 |
|---|---|
| 코드 | `CARD_CODE`(품목코드), `CARD_CODE_ERP`(ERP코드) |
| 분류 | `CARD_TYPE_NAME`(답례품/청첩장/기타), `BRAND_NAME`, `ORIGIN_NAME`, `PRODUCTION_STATUS_NAME` |
| 수량 | `INVENTORY_CURRENT_QTY`, `INVENTORY_AVAILABLE_QTY`, `INVENTORY_REQUEST_QTY` 등 |
| 금액 | `CLOSING_COST`, `CONSUMER_PRICE`, `CARD_SET_PRICE`, `TOTAL_SALE_PRICE_30/90/180/365_DAY` |
| 일자 | `ERP_FIRST_REG_DATE`, `RELEASE_DATE`, `MOD_DATE`, `REG_DATE` |

품목마스터·BOM 성격의 테이블은 없습니다. 이름이 비슷한 `ERP_Price`(134,402행)는
2008년 카드 단가 레거시이고, `S2_CardItem` 은 청첩장 카드 구성 관계라 답례품과 무관합니다.

## 2. 없어서 생긴 문제 (실제 사례)

### 2-1. 상품구분이 없고, 상태 값이 대부분 비어 있다

재고 화면을 답례품 코드 전체로 자동 구성했더니 **290개**가 나왔고, 그중
**스티커 86개**, 그 외 세트·반제·부자재가 섞였습니다. 운영에서 재고를 볼 대상은
원물/상품뿐인데 ERP 의 `상품구분`(세트/반제/원물/스티커/부자재)과 `사용여부`가
`bar_shop1` 으로 넘어오지 않아 걸러낼 수 없었습니다.

`CARD_TYPE_NAME` 은 답례품/청첩장 수준이라 이 용도로는 쓸 수 없습니다.
ERP 화면의 `품목군` 에 해당하는 컬럼이 없습니다.

`상태` 는 `PRODUCTION_STATUS_NAME` 으로 이미 넘어오지만 **156개 중 99개가 빈 값**입니다.
ERP 화면에는 `정상판매` 로 표시되는 품목도 비어 있어 필터로 쓸 수 없습니다.
→ 컬럼 추가가 아니라 **값을 채워주시는 것**만으로 해결됩니다.

> 현재 대응: 운영이 관리 품목을 화면에서 직접 등록해 사용 중

### 2-2. 재고 동기화가 누락된다 ★ 가장 시급

ERP `물류관리 > 스마트재고현황` 에서는 정상 조회되는 품목이 `bar_shop1` 에 없습니다.

`TGJSD11O1` (사양벌꿀120g) — ERP 화면: **현재고 231 / 가용재고 231 / 상태 정상판매**
→ `S2_CARD_ERP_STOCK` 에는 행 자체가 없음 (`CARD_CODE`, `CARD_CODE_ERP` 모두 0건)

ERP 화면의 컬럼은 `S2_CARD_ERP_STOCK` 과 1:1 로 대응합니다
(현재고·가용재고·중국재고·이동재고·미생산량·마감단가·계정·상태·브랜드·카드구분).
즉 스키마 문제가 아니라 **적재 대상에서 빠지는 행이 있는 문제**입니다.

BOM 목록의 원물 코드 22개를 표본 조사한 결과 **12개가 미동기화**였습니다.

```
TGJSD11O1, TGIKX01O1, TGJSD05O2, TGJSD15O1, TGJSD08O2, TGJSD08O3,
TGJSD08O4, TGJBK06O1, TGJBK07O1, TGIBK01O1, TGJSD12O1, TGJSD14O1
```

BOM 파일 기준으로도 재고 대상 구성품(원물·완제품·상품·반제품) 52개 중
**25개만** `bar_shop1` 에 존재합니다. 나머지는 재고 조회가 불가능합니다.

**요청: 적재 조건을 확인해 누락 행을 포함해 주세요.** 이것만 해결되면
아래 A·B 없이도 상당 부분 운영이 가능합니다.

### 2-3. BOM 이 없어 소진량을 수동 관리해야 한다

한 원물이 단독으로도 팔리고 여러 세트에도 들어가, 재고는 그 모든 경로에서 빠집니다.
BOM(세트 → 구성품 + 소요수량)이 없어 어떤 세트가 어떤 원물을 몇 개 쓰는지 알 수 없습니다.

주방세제(`TGJBK03O1`, 현재고 8,156) 최근 30일 실측:

| 판매 경로 | 수량 |
|---|---:|
| 주방세제 500ml 단독 | 58 |
| 송월 주방타올&주방세제 세트 | 86 |
| 주방세제 기프트 세트 | 177 |
| 송월 수건&주방세제 세트 | 8 |

단독 코드만 세면 144개 → 소진예상 1,699일, 전 경로를 세면 329개 → 743일로
**2.3배** 차이가 납니다. 데일리너츠처럼 세트 1개에 원물이 5개 들어가는 경우
배수까지 필요합니다.

> 현재 대응: 화면에 `소진코드`(품목코드 + 배수) 를 수동 입력. 세트 구성이 바뀌면 사람이 갱신해야 함

### 2-4. ERP코드 ↔ 품목코드 매핑이 1:N 이라 모호하다

같은 품목코드가 서로 다른 ERP코드에 달려 있고 재고가 크게 다릅니다.

| 품목코드 | ERP코드 | 현재고 | 수정일 |
|---|---|---:|---|
| `TGJSD01O4_A` | `TGJSD01` | 4,466 | 2026-08-05 |
| `TGJSD01O4_A` | `TGJSD01O4` | 19,061 | 2026-06-17 |

어느 쪽이 유효한지 판단할 근거가 데이터에 없습니다. 답례품 품목코드 166개 중
29개가 ERP코드가 아니고, 그중 7개가 이런 다중 후보 상태입니다.
레거시로 보이는 행은 수량이 `NULL` 이거나 음수(`-1`, `-354`)로 남아 있습니다.

## 3. 요청 항목

### A. 품목마스터 (우선순위 높음)

| 필드 | 용도 |
|---|---|
| 품목코드 (ERP코드) | 키 |
| 품목명 | 표시 |
| **상품구분** | 세트/반제/원물/상품/스티커/부자재/패키지 — 재고 대상 판별 |
| **사용여부** | 사용/미사용/단종 — 단종 품목 제외 |
| 브랜드명 | 그룹핑 |
| 규격·입수 단위 | 수량 해석 |

2-1, 2-2 가 해결됩니다.

### B. BOM (우선순위 높음)

| 필드 | 용도 |
|---|---|
| 세트 품목코드 | 상위 |
| 구성품 품목코드 | 하위 |
| **소요수량** | 세트 1개당 차감 수량 |

2-3 이 해결되고, 소진코드 수동 관리가 없어집니다.

### C. 기존 재고 테이블 보완 (최소안 · 가장 저렴)

A·B 가 어렵다면 아래 두 가지만으로도 상당 부분 해결됩니다.

1. **누락 행 적재** (2-2) — 최우선
2. `PRODUCTION_STATUS_NAME` 값 채우기 + `품목군`(상품구분) 컬럼 추가 (2-1)

### D. 매핑 정리 (데이터 품질)

2-4 의 다중 후보 행에 대해, 유효한 행을 식별할 수 있는 플래그나
폐기 행 정리가 필요합니다. (`유효여부` 컬럼 또는 폐기 행 삭제)

---

## 4. 연동 방식 제안

기존 `S2_CARD_ERP_STOCK` 과 동일하게 **테이블 적재 + 일 1회 갱신**이면 충분합니다.
실시간성은 필요하지 않습니다. 컬럼 추가(C안)만으로도 상당 부분 해소됩니다.

---

## 5. 연동 전까지의 운영

- 재고 관리 품목은 화면에서 수동 등록 (재고코드 = ERP코드)
- 매출코드·소진코드도 수동 지정, 소진코드는 `코드*배수` 형식 지원
- 잘못된 코드는 표에 `⚠`, 재고를 못 찾으면 `❓` 로 표시
- 세트 구성 변경 시 소진코드를 사람이 갱신해야 함 ← **가장 큰 운영 부담**
